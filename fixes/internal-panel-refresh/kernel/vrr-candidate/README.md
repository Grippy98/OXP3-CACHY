# Accepted Intel VRR DC-balance candidate

This adds upstream `c034e8a46e4cb703018fe7e10fe5a3a974d6a7c3` to the corrected display-test revision 3 baseline. The shared Intel display parameter `enable_dc_balance` defaults false and gates the existing computation for Xe/i915. It changes only `intel_display_params.c`, `intel_display_params.h` and `intel_vrr.c`; the EDID retry, two DSB corrections and existing controller support remain.

The original owner accepted controls/motion with internal VRR and the zero-lead Gamescope runtime on **`7.2.9-onex3-vrr-test`**. That setup was persisted and verified by a normal reboot. This kernel does not itself repair the separately observed fixed-refresh scheduling deadline, enable external-dock VRR or establish results for all games.

Use a **copy** of the completed [parent display build](../README.md), without restoring its source/config. The helper validates the exact baseline config/source, applies the new patch, changes only LOCALVERSION and creates a separate `linux-onex3-vrr-test 7.2.9-1` package. Let `tree`, `output`, `packages` and `repo` be absolute paths in your own Linux build workspace; `output` and `output-stage` must not exist.

```sh
recipe="$repo/fixes/internal-panel-refresh/kernel/vrr-candidate"
bash "$recipe/build-vrr-kernel.sh" "$tree" "$output"
bash "$recipe/build-controller-module.sh" "$tree" "$output/controller-module"
bash "$recipe/package-vrr-kernel.sh" "$tree" "$output" "$output-stage" "$packages"
python3 "$recipe/validate-vrr-kernel.py" "$output-stage" "$output-validation.json"
```

The controller module is rebuilt/signed for the changed release; the package must retain UHID/UINPUT and all validated input transports. Build provenance is generated by the helper rather than requiring private session files. Config/source hash checks deliberately refuse an incompatible tree. Changing them is a manual port requiring renewed build/input/hardware testing.

For installation/recovery, follow the [parent manual steps](../README.md). Keep the accepted stock/distribution recovery entry, and verify picture, controller input and actual VRR before changing normal boot selection. No script installs/reboots, edits EFI, enables external PCON parameters or selects a boot default. The full accepted userspace path is documented in [runtime selection](../../permanent/README.md).
